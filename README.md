## 关于这份指南

我用过不少软件、浏览器扩展、开源程序和在线工具。有些一用就离不开，有些只在特殊情况下才需要，也有些尝试之后不打算再装。

我希望把这些经历变成一本**属于自己的数字工具指南**：不仅记下软件的名字和下载地址，更记下**它解决什么问题、为什么值得保留、什么时候需要重新安装**。

这是一份个人精选，而非追求数量的软件下载站。最初使用 GitHub Markdown 维护，将来有时间再把相同内容制作成一个带有怀旧互联网气质的小网站。

## 我的收录规则 · Curation

- **真正使用过**：优先收录实际体验过、愿意重复使用的工具。
- **写清楚理由**：至少能用一句话解释“我为什么保留它”。
- **获取渠道可靠**：尽量链接官方网站、官方 GitHub 或可信的正式商店页面。
- **不追逐版本**：不手工维护每个软件的具体版本号；优先保持下载链接有效。
- **减少重复收藏**：同一需求优先保留最合适的工具，必要时说明备选品。
- **分清收藏与安装**：值得收藏不代表值得在每台设备上长期安装。

### 收藏状态

| 标记 | 含义 |
| --- | --- |
| `常用` | 经常使用，值得长期保留 |
| `按需` | 特定任务才会用到，需要时再安装 |
| `待体验` | 发现了有趣的工具，但尚未形成推荐结论 |
| `停用` | 用过，但目前已有替代或不再推荐安装 |

**待体验列表不等于正式推荐**。收集到新工具时，先记在 [待体验清单](INBOX.md)，实际使用后再决定是否加入对应平台目录。

## 更新方式 · Maintenance

1. 发现工具：先记入 [INBOX.md](INBOX.md)。
2. 实际试用：判断是否解决了真实问题。
3. 值得留下：按照 [软件条目模板](templates/software-entry.md) 写下用途、理由和官方链接。
4. 定期整理：移除重复推荐，修复失效链接，更新重装清单。

保持简单：**软件记录用 Markdown，版本控制交给 Git，未来网站沿用这些内容。**
