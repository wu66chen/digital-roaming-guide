# macOS 清理工具比较：AppCleaner、PureMac、Mole

[← 返回 macOS 收藏](../catalog/macos.md) · [返回指南首页](../README.md)

> 收藏依据：这三款都被列入个人 macOS 必装候选。它们的**定位不同，但存在大量功能重合**。建议明确用途、不要把清理缓存当作每日系统维护。

## 一眼区分

| 对比 | **AppCleaner** | **PureMac** | **Mole（开源 CLI）** |
| --- | --- | --- | --- |
| 主要定位 | 卸载 App 并查找关联文件 | 图形化综合清理、应用管理、存储检查 | 终端清理、卸载、磁盘分析、维护 |
| 使用入口 | 拖放应用到窗口 | 原生图形界面 | `mo` 命令 / 终端菜单 |
| 清理缓存、系统文件 | 不以此为核心 | 支持分类清理 | 支持深度清理、开发缓存 |
| 应用卸载 | 主要功能 | 支持，含孤儿文件扫描 | 支持 |
| 磁盘空间分析 | 非重点 | 支持 | 支持 |
| 强项 | **最简单的日常卸载** | **所见即所得的图形化管理** | **高级批量任务与可预览控制** |
| 主要短板 | 功能范围窄 | 功能重叠、操作范围广；需复核删除内容 | 学习成本高，命令目标错误可能误删 |
| 项目/获取 | [AppCleaner](https://freemacsoft.net/appcleaner/) | [PureMac](https://github.com/momenbasel/PureMac) | [Mole](https://github.com/tw93/Mole) |

## AppCleaner：日常卸载优先

**适合：** 很明确地决定卸载某个 App，希望顺便删除偏好、缓存和其他关联文件。

- **优点**：交互简单；专注解决一个实际问题，扫描后可以自行决定删哪些关联文件。
- **限制**：不是综合磁盘清理器，不负责开发缓存、系统维护或磁盘大文件分析；程序关联文件识别并非零误判。
- **建议**：作为日常卸载工具即可，删除前仍要检查是否涉及需要保留的用户配置、素材或项目数据。

## PureMac：图形化清理与总览

**适合：** 希望在 GUI 中查看缓存、孤儿文件、磁盘空间、应用、更新和系统状态后，有选择地处理。

- **优点**：原生 macOS 图形界面；可以按类别检查、排除项目；涵盖 App 卸载、磁盘、系统检查等多个场景。
- **限制**：和 AppCleaner、Mole 共享大量功能。其官方 README 明确区分：App 卸载等部分项目可进入废纸篓；分类清理、定时清理、清空废纸篓等某些操作可能**永久删除文件**。启动自动清理前务必检查规则。
- **建议**：把它作为“偶尔打开的综合检查面板”，不推荐为了腾空间而常驻自动清理。

## Mole：终端深度处理

**适合：** 习惯终端，希望分析路径、清理开发产生的缓存/构建产物，或做明确可控的维护任务。

- **优点**：功能覆盖广，提供 `mo clean` / `mo uninstall` / `mo analyze` / `mo optimize` 等；有 `--dry-run` 预览、白名单等保护机制。
- **限制**：需要理解命令、路径和结果。`clean`、`purge`、`uninstall` 等可能删数据；即使有安全防护也不能代替人工审核。
- **重要区别**：`brew install mole` 是**免费开源 CLI**；官方另外提供独立的商业原生 GUI 应用，不要把两者当作同一个包。
- **建议**：先只用检查/预览指令，确认清理范围以后再执行；避免无差别清理浏览器或开发工具缓存。

## 是否有必要三款同时安装？

**没有功能上的必要。** 若按个人习惯保留三款，可这样分工：

1. **AppCleaner**：日常卸载 App。
2. **PureMac**：在 GUI 中检查磁盘与残留，必要时才清理。
3. **Mole CLI**：面向确实需要的开发缓存、复杂目录分析与终端操作。

如果你发现自己长期只用 AppCleaner，也可以把 PureMac、Mole 从“必装”调成“按需”。是否调整由之后的真实使用体验决定，不在此擅自更改你的原始收藏分类。

## 清理前的基本安全原则

- 先确认具体问题：磁盘空间不足、某个 App 卸载残留、开发构建缓存过大，或特定程序异常。
- 先审核候选路径，再决定是否清理；**缓存可以重新生成，不等于删除毫无代价**。
- 不批量删除 `~/Library` 中不熟悉的目录，不清理当前项目/模型/素材，不对陌生清理命令直接加 `sudo`。
- PureMac 的自动清理、Mole 的实际删除操作优先关闭或使用预览，备份关键数据后再执行。
- 不要把“释放 RAM”“系统优化百分比”作为长期工具价值判断标准。
