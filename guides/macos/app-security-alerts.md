# macOS｜应用无法打开：开发者无法验证 / App 已损坏

**适用场景：** 安装 App 后，macOS 提示开发者无法验证、Apple 无法检查是否包含恶意软件，或提示 App 已损坏。

**前提：** 只处理来源可信且未被篡改的软件。不同错误提示可能有不同原因，先看清原文。

## 处理步骤：无法验证开发者 / 无法检查恶意软件

1. 从可信来源重新确认安装包，尝试打开 App 一次，记下系统提示。
2. 打开 **系统设置 → 隐私与安全性**，向下滚动至 **安全性**。
3. 如果出现该 App 的 **「仍要打开」**，确认来源可信后点击；按系统提示输入密码，再选择 **「打开」**。
4. 重新打开 App，验证是否可以正常运行。

> 「仍要打开」通常在尝试启动后的一段时间内出现；如果没有此选项，不要直接尝试全局关闭安全防护。参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

## 不同提示怎么处理

| 系统提示 | 优先做法 |
| --- | --- |
| 无法验证开发者 | 确认来源可信后，尝试上述「仍要打开」流程 |
| Apple 无法检查是否包含恶意软件 | 先找官方公证版本；确需运行时再按系统允许的例外流程操作 |
| App 已损坏，无法打开 | 先重新从官方渠道下载，检查文件是否完整或被修改；不要假定是来源限制 |
| App 将损坏你的电脑 / 已检测到恶意软件 | 停止运行并删除可疑软件；不要绕过拦截 |

## 高级记录：允许「任何来源」（不建议作为日常解决办法）

以下是旧有的全局设置方式，涉及降低系统的应用安全检查强度；在不同 macOS 版本中可能需要系统设置确认，且命令的支持情况存在变化。**优先使用针对单个 App 的「仍要打开」。**

```bash
# 查看 Gatekeeper 评估状态
spctl --status

# 旧有全局关闭命令（高风险，仅记录，不建议日常执行）
sudo spctl --master-disable

# 恢复全局评估
sudo spctl --master-enable
```

如果确实曾启用「任何来源」，处理完成后应在 **系统设置 → 隐私与安全性 → 安全性** 中恢复为 **「App Store 和被认可的开发者」**，再使用 `spctl --status` 检查状态。此操作不能修复真正损坏或存在恶意代码的 App。

## 验证与记录

- **成功标准：** 所需 App 可正常打开，且未关闭全局安全保护。
- **失败时：** 记录 macOS 版本、App 名称和版本、完整报错、安装包来源，再按具体错误排查。
- **实机验证：** 待填写（设备 / macOS 版本 / 验证日期）。
